# Synthetic Bug-Injection Mutants

Alongside historical upstream `libsignal` commits (`cheval26-*` in [`../README.md`](../README.md)), this directory maintains **synthetic regression mutants** (`kind = "synthetic"` in [`third_party/libsignal/bug-injection/synthetic/bugs.toml`](../../../third_party/libsignal/bug-injection/synthetic/bugs.toml)). Each mutant is a small forward Rust patch against `libsignal v0.105.4` that introduces a realistic protocol or key-erasure bug—such as dropping the post-quantum ratchet secret, leaking a MAC key in an unencrypted header, forgetting to wipe rotated-out private keys from disk, or skipping ciphertext MAC verification—used to test that our top-level `signal-session` security specification (`SignalSessionSecure` / `CompRefinesCliElf`) actually catches real implementation bugs.

---

## What Each File Means

Every synthetic mutant is represented by four artifacts that work together in the bug-injection pipeline (`python3 scripts/bug_injection.py`):

- **Patch** (`third_party/libsignal/bug-injection/synthetic/patches/<bug>/v0.105.4.diff`): The forward Rust diff applied to a clean `libsignal v0.105.4` checkout to introduce the bug. `scripts/bug_injection.py verify-patches` checks its SHA-256 hash and verifies that it applies cleanly at `v0.105.4`.
- **Witness** (`third_party/libsignal/bug-injection/synthetic/witnesses/<witness>.json` → `Symbolic/BugInjection/Synthetic/Witnesses/<Name>.lean`): The concrete attack scenario and its recorded trace. The JSON file specifies the sequence of `signal-session` CLI commands (`init`, `send`, `recv`, `clear`) and disk compromise events (`leak`) the test harness runs. Running `scripts/bug_injection.py run` executes that scenario on both the patched Rust binary and unmodified `libsignal v0.105.4`, checks that their observable traces differ (`live`), and records the mutant's exact `CliEvent` trace into `Synthetic/Witnesses/<Name>.lean`.
- **Non-vacuity** (`Symbolic/BugInjection/Synthetic/NonVacuity/<Name>.lean`): A kernel-checked Lean theorem (`nonvacuous : ∃ i r, fits i r`, compiled automatically in the default `lake build`) proving that the witness's concrete public keys, ciphertexts, and external cryptographic contracts are mutually satisfiable. This guarantees that a specification disproof genuinely rejects the buggy trace rather than succeeding vacuously from contradictory setup assumptions.
- **Disproof** (`Symbolic/BugInjection/Synthetic/Disproofs/<Name>.lean`): The per-mutant Lean refutation module, elaborated only when `scripts/bug_injection.py disproof` re-extracts the patched ARM64 machine code and links the mutant's `signal-session` ELF (`CV_BUG_INJECTION=<bug>`). Each module states `theorem disproof : ¬ DY.Libsignal.Composed.Security.SignalSessionSecure mutantCliElfBytes`—the exact negation of the headline security theorem on the mutant binary—designed to be discharged via `not_signalSessionSecure_of_witness` ([`Witnesses/CliShape.lean`](../Witnesses/CliShape.lean)) from a machine-free **spec half `(S)`** (showing no valid symbolic execution or collision excuse explains the recorded buggy trace) and an **implementation half `(I)`** (showing the patched ARM64 ELF produces that trace).

## Plain-Language Descriptions of the Mutants

### `synthetic-spqr-key-drop` — Dropping the Post-Quantum Ratchet Key

In `libsignal v0.105.4`, every session runs a Triple Ratchet: the classical X25519 Double Ratchet produces a 32-byte message seed, while the Sparse Post-Quantum Ratchet (`spqr` crate, using ML-KEM-768 braids) produces an optional 32-byte post-quantum message key (`pqr_key`), and `MessageKeyGenerator::generate_keys` combines the two by passing `pqr_key` as the HKDF-SHA256 salt when deriving message encryption and MAC keys. This mutant discards `pqr_key` and calls `MessageKeys::derive_keys(&seed, None, counter)` instead. All SPQR state transitions and wire tokens continue to serialize onto the network so packets look structurally normal, but the post-quantum secret is thrown away right before symmetric key derivation—silently downgrading the Triple Ratchet to a classical Double Ratchet with no post-compromise quantum healing.

### `synthetic-addr-key-leak` — Leaking the MAC Key in Wire Metadata

On initial unacknowledged `0x03` `PreKeySignalMessage` sends, `libsignal v0.105.4` populates `SignalMessage` protobuf field 6 (`addresses`) with the 36-byte serialized sender and recipient `ProtocolAddress` UUID pair (while `0x02` whisper messages omit field 6). This mutant replaces that serialized address pair in `SignalMessage::new` with `Some(mac_key.to_vec())`, broadcasting Alice's raw 32-byte per-message HMAC key in cleartext inside protobuf field 6 on her very first `send`. Any passive network observer can read `mac_key` directly off the wire and forge authenticated messages to Bob.

### `synthetic-unack-prekey-omitted` — Omitting the Initial `PreKeySignalMessage` Envelope

When Alice initiates a session from Bob's pre-key bundle, she must wrap her encrypted `SignalMessage` inside an outer `0x03` `PreKeySignalMessage` envelope carrying her identity key, ephemeral base key, Kyber-1024 ciphertext, and the IDs of Bob's pre-keys until she decrypts Bob's first reply. This mutant deletes the `set_unacknowledged_pre_key_message` and `set_unacknowledged_kyber_pre_key_id` calls in `process_prekey_bundle`. As a result, Alice's very first `send` emits a bare 106-byte `0x02` whisper `SignalMessage` instead of a 1,797-byte `0x03` `PreKeySignalMessage`, omitting all handshake key material so Bob has no way to establish the session.

### `synthetic-recv-chain-priv-retained` — Retaining Rotated-Out Ratchet Private Keys on Disk

`libsignal`'s `SessionStructure` protobuf reuses a single `Chain` message schema for both the active `sender_chain` (which stores a 32-byte `sender_ratchet_key_private` in field 2) and the list of up to five `receiver_chains` (which only need the peer's public ratchet key, so honest code sets `sender_ratchet_key_private: vec![]`). During `RatchetState::dh_ratchet_step`, this mutant copies the party's rotated-out `sender_private_key` into `receiver_chains[*].sender_ratchet_key_private` instead of clearing it. Wire traffic looks identical to clean `libsignal`, but up to five generations of rotated-out X25519 private keys remain sitting in the session file on disk—allowing an attacker who compromises the device after multiple DH ratchet steps to recover past private keys and break Post-Compromise Security.

### `synthetic-keep-opk` — Failing to Delete a Consumed One-Time Pre-Key

In Signal's PQXDH handshake, Bob's signed pre-key and last-resort Kyber pre-key are medium-term keys rotated periodically, whereas Bob's One-Time Pre-Key (`OPK`) provides immediate forward secrecy for Alice's initial handshake: as soon as Bob decrypts a `PreKeySignalMessage` naming `pre_key_id`, `message_decrypt_prekey` calls `pre_key_store.remove_pre_key(pre_key_id)` to wipe that private key from Bob's disk. This mutant skips `remove_pre_key`, leaving Bob's 32-byte OPK private key intact inside `bob/one-time-pre-keys/` after the handshake completes. If Bob's device is later compromised, the attacker still recovers the consumed OPK private key needed to reconstruct the handshake secret (and can replay or reuse the same "one-time" pre-key across additional sessions).

### `synthetic-verify-mac-skip` — Skipping Ciphertext MAC Verification

Every Signal ciphertext ends with an 8-byte truncated HMAC-SHA256 tag computed over the sender and receiver identity public keys, the protocol version byte, and the serialized `SignalMessage` protobuf. This mutant ignores the constant-time `our_mac.ct_eq(their_mac)` comparison in `SignalMessage::verify_mac` and unconditionally returns `Ok(true)`. When an active network attacker overwrites the trailing 8-byte MAC tag on Alice's message with `ffffffffffffffff` (or flips chosen bits in an AES-256-CBC ciphertext), clean `libsignal v0.105.4` immediately exits with an authentication error (`exit 1`), whereas the mutant accepts the forged packet (`exit 0`) and outputs plaintext.

### `synthetic-promoted-prekey-headers` — Skipping Outer Identity Checks on Session Promotion

Until Alice receives Bob's first reply, every message she sends is wrapped in an outer `0x03` `PreKeySignalMessage` carrying her `identity_key` and ephemeral `base_key`. When Bob receives a second bundled `PreKeySignalMessage` whose `base_key` matches an already-established session, clean `libsignal v0.105.4` still verifies `identity_store.is_trusted_identity(remote_address, their_identity_key, Receiving)` before calling `promote_matching_session` and saving `their_identity_key`. This mutant promotes a matching `base_key` session before the `is_trusted_identity` check. When an active attacker swaps the outer `identity_key` on a bundled `PreKeySignalMessage` with a foreign key, clean `libsignal` rejects (`exit 1`), whereas the mutant accepts (`exit 0`), decrypts the inner whisper ciphertext, and overwrites Bob's pinned identity file for Alice on disk.

### `synthetic-implicit-reject-mac` — Accepting Unauthenticated Handshakes on Kyber Implicit Rejection

CRYSTALS-Kyber-1024 uses the Fujisaki–Okamoto transform with implicit rejection: decapsulating a tampered `kyber_ciphertext` does not return an error, but instead returns a pseudorandom fallback shared secret that causes subsequent inner `SignalMessage` HMAC-SHA256 verification to fail inside `try_decrypt_from_record`. This mutant replaces `try_decrypt_from_record(...)?` in `message_decrypt_prekey` with `.unwrap_or_default()`. When an attacker corrupts `kyber_ciphertext` and zeroes the trailing 8-byte inner `SignalMessage` MAC, clean `libsignal v0.105.4` rejects (`exit 1`) without modifying Bob's state, whereas the mutant exits `0` with empty plaintext and persists the unauthenticated session to disk.

### `synthetic-evicted-chain-skipped-key` — Accepting Skipped Keys from Evicted Receiver Chains

In `libsignal v0.105.4`, `RatchetState::dh_ratchet_step` maintains a bounded FIFO ring buffer of at most `MAX_RECEIVER_CHAINS = 5` peer ratchet public keys; because skipped message keys live inside each `Chain` entry (`receiver_chains[i].message_keys`), evicting the oldest `Chain` after five subsequent peer DH ratchets simultaneously erases any unconsumed skipped message keys from that epoch. This mutant deletes the `while self.receiver_chains.len() > consts::MAX_RECEIVER_CHAINS` eviction loop in `dh_ratchet_step`. After Alice sends messages 0 (`skip-0`) and 1 (`init-1`) on her initial ratchet key and five subsequent ping-pong DH ratchets advance the session, clean `libsignal v0.105.4` has evicted epoch 0 and rejects a delayed delivery of message 0 (`exit 1`), whereas the mutant retains skipped keys indefinitely and decrypts it (`exit 0`).

### `synthetic-zero-base-key-pqxdh` — Accepting Zero / Low-Order `base_key` in PQXDH Handshakes

In `libsignal v0.105.4`, `pqxdh_accept` validates `parameters.their_ephemeral_key.is_canonical()` before any Diffie-Hellman computation and propagates `calculate_agreement(...)?` errors whenever `their_ephemeral_key` is a low-order X25519 point whose shared secret is all zeroes. This mutant omits the `is_canonical()` check and replaces `calculate_agreement(&parameters.their_ephemeral_key)?` with `.unwrap_or_else(|_| Box::new([0u8; 32]))`. When an active participant knowing `DH(ikA, spkB)` substitutes `base_key = 0x05 ‖ 0^32` on Alice's initial `PreKeySignalMessage` (preserving her honest Kyber-1024 ciphertext and SPQR `pq_ratchet` header) and re-encrypts/MACs `forged!!!` under `DH2 = DH3 = 0^32`, clean `libsignal v0.105.4` rejects (`exit 1`), whereas the mutant accepts (`exit 0`) and outputs `forged!!!`.
