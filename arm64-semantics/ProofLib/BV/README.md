# `ProofLib/BV`: Kernel-Checked `BitVec` Normalizers and Decision Procedures

`ProofLib/BV/` contains fast, kernel-checked decision procedures and normalizers for `BitVec` and `Nat`/`Int` arithmetic obligations arising during AArch64 symbolic execution and framing.

Unlike `bv_decide` (which invokes an external SAT solver and embeds `Lean.ofReduceBool` native-evaluation certificates taking 70–200 ms per call), `bv_lin`, `bv_arith`, and `bv_bits` construct ordinary Lean 4 kernel terms (reflection by `Eq.refl true`, bound-driven `toNat` lemma chains, and `omega`) in under a few milliseconds.

## Solver Selection Guide: `bv_solve` vs `bv_arith` vs `bv_lin` vs `bv_bits`

| Tactic / API | Fragment Handled | Uses Context Hypotheses? | Kernel Mechanism | Typical Speed | When to Use |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **`bv_lin`** (`@[bv_lin_norm]`) | Purely algebraic linear `BitVec w` equalities (`=`) and disequalities (`≠`): `+`, `-`, unary `-`, `* c`, `<<< c`, and `BitVec.ofNat w <linear Nat>` (supports generic width `w`) | **No** (ignores hypotheses) | Reflective polynomial normal form (`Lin.Poly`, `Eq.refl true`) | **< 1 ms** | Address offset identities (`sp - 16 + 8 = sp - 8`), constant-offset disequalities (`a + 8 ≠ a + 16`), or normalizing linear `BitVec` expressions via `simp only [bv_lin_norm]`. |
| **`bv_arith`** | Linear `BitVec` / `Nat` / `Int` arithmetic with hypotheses: `+`, `-`, `* c`, `<<< c`, `>>> c`, `/ c`, `% c`, `ult`/`ule`/`slt`/`sle`, `zeroExtend`/`truncate`/`extractLsb'`, contiguous masks (`&&& 0xfff`, ADRP page masks) | **Yes** (relevance-filtered to atoms shared with the goal) | Tries `bv_lin` first on `=`/`≠`, then translates relevant nodes to `toNat`/`toInt` via interval-cached no-wrap lemmas (`ub_*`/`lb_*`) + 1 `omega` call | **1–10 ms** | Drop-in replacement for `bv_omega`: bounds checks, non-wrapping pointer arithmetic, loop index bounds, ADRP page alignment, and unsigned/signed comparisons. |
| **`bv_bits`** (`@[bv_bits_nat]`) | Bit-structure mixed with arithmetic: literal bitmasks (`x &&& c`, `x &&& ~~~7`), bit-disjoint `|||` (`a ||| b = a + b`), byte concatenation (`++`), `extractLsb'`, `setWidth`, and `if c then t else e` splits | **Yes** | Generalizes `ite` subterms, rewrites bitwise ops into `Nat` `/`, `%`, `*` runs of ones (`@[bv_bits_nat]`), adds bitwise bounds, and runs `omega` | **5–25 ms** | Bitfield extraction/packing, alignment masks (`(sp - 512) &&& 15 = 0`), byte assembly (`++`), and conditional bitvector expressions where you want a pure kernel proof (no `ofReduceBool`). |
| **`bv_slice`** | Pure bit-slice / bitfield `BitVec` and `Bool` goals (`&&&`, `|||`, `^^^`, `~~~`, `<<< c`, `>>> c`, `sshiftRight c`, `++`, `extractLsb'`, `zeroExtend`, `signExtend`, `replicate`, `getLsbD`, `msb`, `=`, `≠`, `∧`, `∨`, `¬`, `→`, `↔`) | **Yes** | Per-lane structural ROBDD normalizer (`SBDD`, `prove_of_checkSlice`, `Eq.refl true`, `0` `ofReduceBool`) | **20–700 ms** (kernel `Eq.refl` dominates; measured on `Examples/Testing/ProofLib/BVReflectOptionA.lean`) | Bitfield extraction/packing, multi-byte 7-bit varint assembly, shift/mask identities, and `extractLsb'` over `++`. |
| **`bv_robdd`** | Full bit-slice fragment **plus** ripple-carry arithmetic & comparisons (`+`, `-`, `neg`, `==`, `!=`, `<`/`ult`, `≤`/`ule`, `slt`, `sle`, `ite`, `AddWithCarry64`/`32`, `ConditionHolds`) | **Yes** | Interleaved LSB-to-MSB witnessed ROBDD verifier over `BinTree BDDNode` (`prove_of_checkROBDD`, `Eq.refl true`, `0` `ofReduceBool`) | **0.06–5 s** at 64-bit (kernel `Eq.refl` dominates; ripple-carry/`ConditionHolds` goals ≈3–5 s) | Mixed bitwise + arithmetic identities (`x &&& -8 = x - (x &&& 7)`, `(r - 1) &&& r ≤ r`, `x ^^^ y = (x ||| y) - (x &&& y)`), `AddWithCarry64` NZCV flags, and branch classification hypotheses. |
| **`bv_solve`** | **All of the above + general bitwise/SAT:** syntactically classifies the goal (`GoalClass`) and dispatches **one** solver (`ground → decide`, `linearEq/linearArith → bv_arith`, `bitwise/symbolicShift → bv_decide` on filtered hyps) | **Yes** (relevance-filtered) | Single-solver dispatch via `ArithClassify.classify` (`trace.bv_solve` logs choice) | **1–10 ms** (linear) / **70–150 ms** (SAT) | General-purpose one-shot `BitVec` closer when a goal may be either linear arithmetic or general bitwise logic (`^^^`, symbolic shifts, non-contiguous bit tricks). |
| **`decideProp?`** (`MetaM` API) | Decides whether a proposition `p : Expr` is provable (`some (true, pf)`), refutable (`some (false, pf)`), or undetermined (`none`), pre-filtering via concrete test vectors (`evalVerdict`) | **Yes** | Concrete counterexample filter (`evalVerdict`) followed by `bv_arith` (and optionally `bv_decide`) | **< 1 ms** on undetermined goals | Inside custom tactics (`wp_steps` branch resolution, `SpecAudit` vacuity checks) to test if a branch condition or disjointness side condition is determined by current hypotheses without wasting solver time. |

## Architecture of `ProofLib/BV/`

1. **Component A — Certified Linear Normal Form (`Attr.lean`, `Linear.lean`, `LinearTests.lean`, `IntegrationTests.lean`):**
   - Reifies linear `BitVec w` and `Nat` expressions into `Lin.Expr` / `Lin.NExpr` and normalizes them into canonical sorted polynomials `Lin.Poly`.
   - Exposes the `bv_lin` tactic, the `@[bv_lin_norm]` simproc, and the `MetaM` helpers `Lin.linearize`, `Lin.diffConst?` (used by `VCGen` / `WP` to compute constant byte offsets between arbitrary linear address expressions), `Lin.proveEq?`, and `Lin.proveNe?`.
2. **Component B — Relevance-Filtered Bound-Driven Arithmetic & Mask Bridges (`ArithAttr.lean`, `ArithLemmas.lean`, `MaskLemmas.lean`, `ArithCore.lean`, `ArithClassify.lean`, `ArithTranslate.lean`, `Arith.lean`, `ArithTests.lean`):**
   - `ArithLemmas.lean` proves the fixed library of Prop-normalization (`norm_*`), node translation (`node_*`), interval bound (`ub_*`, `lb_*`), and reusable pointer-offset / comparison / subtraction / alignment-mask lemmas (exported in both `BitVec` and `ProofLib.BV.Arith`: `toNat_addOfNat`, `or_one_eq_add_one_of_lsb_false`, `add_ofNat_beq_add_ofNat_false`, `add_ofNat_ult_add_ofNat`, `ult_self_add_ofNat_false`, `ult_ofNat64_of_lt`, `ule_ofNat64_of_le`, `add_ofNat_sub_add_ofNat`, `sub_ofNat_add_ofNat_of_le`, `ofNat_add_sub_cancel`, `ofNat64_and_7`, `ofNat64_and_mask8`, `and_neg8_eq_sub_and_7`, `mask_align8_roundtrip`).
   - `MaskLemmas.lean` provides untagged, width-polymorphic power-of-two mask-to-modulo bridges (`toNat_and_twoPow_sub_one`, `and_twoPow_sub_one`, `toNat_and_eq_mod`, `toNat_and_1`..`toNat_and_65535`), chunk-remainder subtraction and comparison lemmas (`toNat_twoPow_sub_and`, `sub_and_pos_le_of_lt`, `ult_and_add_one_eq_false`), alignment equivalences (`and_eq_zero_iff_mod_eq_zero`), and complement align-down identities (`and_not_eq_sub_and`, `and_compl_eq_sub_and`, `toNat_and_compl_eq_div_mul`) exported in `BitVec` and `ProofLib.BV.Arith`.
   - `ArithCore.lean` implements the relevance filter (`relevantHyps` + dangling-register pruning) so large symbolic-execution contexts (50+ register/memory hypotheses) are trimmed to only the 2–5 hypotheses sharing atoms with the goal.
   - `ArithTranslate.lean` walks arithmetic `BitVec` nodes and uses a lightweight 2-step interval cache (`ub`/`lb`) to emit wrap-free `toNat` equations whenever no-overflow is provable from bounds, avoiding exponential `omega` case splits on `% 2^64`.
   - `ArithClassify.lean` provides `classify` (syntactic `GoalClass` classification) and `evalVerdict` (concrete test-vector evaluation to skip unprovable goals in `decideProp?`).
   - `Arith.lean` ties the pipeline together into `bv_arith`, `bv_solve`, `bv_kernel` (`bv_fallback`: kernel-only `bv_ext_bool | bv_bits | bv_omega` fallback chain), and `decideProp?`.
3. **Component C — Kernel-Checked Bit-Structure Normalizer (`BitsAttr.lean`, `Bits.lean`, `BitsTests.lean`):**
   - Generalizes `if c then t else e` subterms and translates `BitVec` bit-manipulation operations (`&&&` with literal masks decomposed into bit runs `[a, a+n)`, bit-disjoint `|||`, `^^^` with literals, `++`, `extractLsb'`, `zeroExtend`/`truncate`) into `Nat` div/mod arithmetic (`@[bv_bits_nat]`) closed by `omega`.
4. **Component D — Kernel-Reflective Bit-Slicer & Witnessed ROBDD Normalizer (`ReflectROBDD.lean`, `Examples/Testing/ProofLib/BVReflectOptionA.lean`):**
   - **Tier 1 (`bv_slice`)**: Evaluates each bit lane $i \in [0, w)$ into a structural ROBDD (`SBDD`) with zero carry chains (`prove_of_checkSlice` closed by `Eq.refl true`).
   - **Tier 2 (`bv_robdd`)**: Orders bit variables interleaved from LSB to MSB so ripple-carry `+`, `-`, `neg`, `ult`, `ule`, `slt`, `sle`, and `AddWithCarry64` flags have $O(1)$ cross-section width, builds the reduced ROBDD DAG (`BinTree BDDNode`) and gate-step witness table (`BinTree (List GateStep)`) in `MetaM`, and verifies every Shannon cofactor recurrence in the kernel in $O(|G| \log |G|)$ steps (`prove_of_checkROBDD` closed by `Eq.refl true`).
   - **Pre-pass (both tiers)**: `preprocessMulPow2` runs the `bvMulPow2` simproc on the target and `Prop` hypotheses, rewriting multiplication by a power-of-two `BitVec` literal on either side (`x * 4#32`, `8#64 * x`, `x * (16 : BitVec w)`) to a constant shift `x <<< k` via the kernel-checked lemmas `mul_eq_shl_of_eq_two_pow` / `mul_eq_shl_of_eq_two_pow'`. Other products (`x * 3#w`, `x * y`) are still abstracted as opaque atoms. `bv_slice` still rejects the remaining `+`/`-`; use `bv_robdd` for those.
