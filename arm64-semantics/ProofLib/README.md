# `ProofLib`: Untrusted Verification Infrastructure and Automation

`ProofLib/` contains the theorems, proof rules, and tactics used to verify AArch64 machine code against the trusted semantics and specification vocabulary in [`Arm64/`](../Arm64/) (see [`Arm64/Trusted/README.md`](../Arm64/Trusted/README.md)). Everything in this directory is `Role::Proof`, **checked by the Lean 4 kernel**, and lies outside the Trusted Computing Base (TCB): a bug in a tactic can cause a proof to fail to construct, but cannot prove a false specification. ProofLib contains no `Role::Spec` modules (`check-trust-guards` rejects any `ProofLib` module named `Spec`); the definitions that surface specs are written in (`c_spec`/`rust_spec`, `c_type_spec`, separation logic, subroutine hooks) live in `Arm64/Trusted/Spec/`, and the lemmas about them live here, together with untrusted convenience definitions that trusted specs may not use (typed ABI combinators `Spec.split` / `Spec.rust*`, `AgreesOutside`, the `ProofLib.Allocator` libc model).

**Lake package.** [`ProofLib/lakefile.toml`](lakefile.toml) defines the `prooflib` Lake package (`srcDir = ".."`), which requires only the trusted `arm64` package ([`Arm64/lakefile.toml`](../Arm64/lakefile.toml)). `lake -d ProofLib build` builds `Arm64` and `ProofLib` into `Arm64/.lake/build` and `ProofLib/.lake/build` without `Examples` on `LEAN_PATH` and without a Rust toolchain, so `ProofLib` cannot import `Examples`. The root `lakefile.lean` requires `prooflib`.

## Start Here (New Proof Author Path)

> **User Guide Index:** For the ordered reading list separating **using the engine** (writing specs & proofs in a campaign or downstream repo) from **developing the engine**, start at `docs/dev/guides/README.md`.

1. **Write or read the specification (`Role::Spec`):** Public C/Rust contracts live in `Spec/Top.lean` (`import Arm64` only) using `c_type_spec` (`docs/dev/c-type-specs.md`), `c_spec`, or `rust_spec` (`docs/dev/guides/writing-specs.md`). State the strongest contract (`onPanic = ⌜False⌝` by default) unless a panic such as allocator OOM is genuinely reachable under `pre`. Audit new specs before proving them with `#spec_nonvacuous!`, `#spec_lint!`, and `#spec_smoke` (`docs/dev/spec-sanity-checks.md`).
2. **Enter the function proof in pure `SepWP` by default (`wp_entry`):** In your `Proofs/*.lean` file (`import ProofLib`), start a `Program.subroutineOk` or `subroutine_ok` proof with `wp_entry` (`ProofLib/SepLogic/Entry.lean`) to reason in pure `SepWP` (`onPanic = ⌜False⌝`), which keeps `sym_block`, `wp_sym_steps`, `wp_steps`, `wp_call`, and `wp_loop_measure` directly usable; weaken afterwards if needed via `subroutine_ok_mono` or `SepWPp.of_sepWP_ret`. Use `wpp_entry` (`SepWPp`) **only** when a panic is genuinely reachable under `pre`, and cut straight-line work into pure `SepWP` segments with `SepWPp.of_sepWP` / `wp_cut_call` / `sepWPp_cut_call` (`docs/dev/guides/writing-proofs.md` §2.1). For `c_type_spec` contracts, unfold semantic types with `simp only [ctype_simp]` (`ProofLib/CType.lean`).
3. **Step basic blocks (`sym_block` / `wp_sym_steps`):** Step straight-line and branching basic blocks with the reflective block executor `sym_block` ([`ProofLib/SepLogic/SymBlock/README.md`](SepLogic/SymBlock/README.md)) or the `SymM` stepper `wp_sym_steps` (`ProofLib/SepLogic/SymWP.lean`). Split unresolved conditional branches with `wp_if` (or `wp_if_join` at diamond reconvergence points), discharging unreachable bounds-check or unwrap branches in `SepWP` from preconditions.
4. **Verify calls and loops (`wp_call`, `wp_loop_measure`):**
   - At `BL` call sites, apply callee or hook contracts with `wp_call` on `SepWP` goals (or `wpp_call` / `wpp_call_frozen` / `SepWPp.call_allowPanic_ret` at panicking calls in `SepWPp`; `ProofLib/SepLogic/WP/ControlTactics.lean`, `ProofLib/SepLogic/WPFrozen.lean`, `ProofLib/SepLogic/WPp.lean`). Use `wp_steps_to_call`, `wp_cut_call`, and `code_call_addr%` (`ProofLib/SepLogic/CodeLookup.lean`) to avoid hard-coding instruction counts or byte offsets.
   - At loop headers, use `wp_loop_measure`, `wp_loop_list`, or `wp_nested_loop` (`ProofLib/SepLogic/LoopTactics.lean`) and the underlying `SepWP.loop_fuel` / `SepWP.loop_measure` combinators (`ProofLib/SepLogic/CFG.lean`). For byte-fill and byte-copy loops, use `ByteSlice.fillPrefix` / `ByteSlice.copyPrefix` and `byte_region_eq` (`ProofLib/SepLogic/ByteRegion.lean`).
5. **Close postconditions and arithmetic (`wp_done`, `sep_frame`, `ProofLib/BV`):** Finish at `RET` with `wp_done`, discharge spatial framing with `sep_frame` ([`ProofLib/SepLogic/README.md`](SepLogic/README.md)), and close `BitVec` side conditions with the kernel-checked solvers `bv_solve`, `bv_arith`, `bv_lin`, `bv_bits`, `bv_slice`, or `bv_robdd` ([`ProofLib/BV/README.md`](BV/README.md) — `bv_decide` is rejected by CI in `Examples/`). See `docs/dev/guides/writing-proofs.md` for the end-to-end walkthrough.

## Directory Map (One Line per Subdirectory)

- [`ProofLib/SepLogic/`](SepLogic/README.md) — Byte-granular separation logic (`↦₆₄`, `↦ᵣ`, `↦ₛ`), backtracking frame solver (`sep_frame`, `sep_entail`), interactive `SepWP`/`SepWPp` tactics (`wp_entry`, `wpp_entry`, `wp_call`, `wpp_call`), reflective `sym_block` ([`SepLogic/SymBlock/README.md`](SepLogic/SymBlock/README.md)), `wp_sym_steps`, CFG/loop combinators (`wp_loop_measure`, `SepWP.loop_fuel`), and `ByteRegion`.
- [`ProofLib/Hoare/`](Hoare/README.md) — Hoare loop rules, step-indexed partial-correctness safety (`safe_until`, `SepWP_idx`), trace-agnostic `subroutine_ok` outcome combinators (`SubroutineOk.lean`), extern/libc/allocator hooks (`HookOk`, `HookMap`, `SubroutineHook`), indirect calls (`FnPtr`), and monadic oracle hooks (`OracleHook`).
- [`ProofLib/Abi/`](Abi/README.md) — Untrusted AAPCS64 ([`Abi/Aapcs/README.md`](Abi/Aapcs/README.md)) and `extern "Rust"` ([`Abi/Rust/README.md`](Abi/Rust/README.md)) calling-convention combinators (`Spec.split`, `Spec.fn*`, `Spec.rust*`) and Rust global allocator / `Vec<T>` / `Box<[T]>` heap models (`ProofLib/Abi/Rust/Heap.lean`).
- `ProofLib/CType/` (`ProofLib/CType.lean`) — Untrusted proof support for `c_type_spec` contracts (`@[ctype_simp]` unfolding lemmas, `#c_type_report`, `LinkedImage.subroutineOk_refine`; see `docs/dev/c-type-specs.md`).
- [`ProofLib/BV/`](BV/README.md) — Kernel-checked `BitVec` decision procedures (`bv_solve`, `bv_arith`, `bv_lin`, `bv_bits`, `bv_slice`, `bv_robdd`, `bv_kernel`) and opt-in width/address normalizers (`width_norm`, `addr_norm`).
- [`ProofLib/Disproof/`](Disproof/README.md) — Machine-code counterexamples and refutations (`¬ subroutine_ok`, `¬ safe_subroutine_ok`, `ReachesException`, defensive `strictHook`, sparse state builder `mkDisproofState`).
- `ProofLib/Library/` (`ProofLib/Library.lean`) — Compositional multi-object library verification (`LibrarySpec`, `LinksIn`, `library_ok.discharge`, `Obj.Image.CallInv`, `Contract.holds_of_callFn`).
- `ProofLib/ProgramReflection/` (`ProofLib/ProgramReflection.lean`) — $O(\log N)$ reflective `WordTree` instruction/symbol lookup, balanced `IdxTree` indexing (`IdxTree.lean`, `idx_tree_of%`), $O(n \log n)$ sorted key-freshness (`SortedFresh.lean`), and binary variant / trap-stub transfer (`Variant.lean`, `#derive_variant`, `trap_transfer`).
- [`ProofLib/ProofTerm/`](ProofTerm/README.md) — Kernel type-checking cost profilers (`#kernel_profile`, `#kernel_hotspots`), static kernel hotspot lint (`#kernel_lint`), and proof-term hygiene tactics (`kfold`, `clear_dead`).

## Quick Lookup Table: Which File to Import or Read for `X`

> **Trust-Guard Rule for `Spec.lean` files:** `Role::Spec` modules (`Arm64.lean` + `Arm64/Trusted/`, `Examples/**/Spec*.lean`, `CaseStudies/**/Spec*.lean`, `Examples/Generated/*Obj.lean`, `CaseStudies/*/Generated/*Obj.lean`) may **only** import `Role::Spec` modules (`Arm64.*` and other `Spec` modules) and therefore can never import `ProofLib.*`. ## High-Level Architecture

- **Symbolic State Normalization (`@[arm64_norm]`):** Curated rewrite rules and simprocs reduce single-instruction execution steps (`execInst`) and register/flag/SIMD updates into canonical read-over-write expressions in $O(1)$ per instruction, while bridging instruction fetches from executable memory (`Program.fetchMem`) to static code-image lookups (`Program.fetch`) via the frozen-memory invariant (`Step.keepsFrozen`).
- **Reflective Separation Logic and Block Framing (`SepLogic/`):** Rather than commuting every memory read past every prior store ($O(N^2)$ disjointness goals), spatial assertions are modeled as multisets of typed or untyped byte blocks (`IsBlock`, `SepBlock`). Rearrangement, frame inference, and cancellation are discharged by one reflective certificate (`SepTree.eq_of_sortIdx`: balanced atom table plus a merge-sorted index comparison, $O(N \log N)$ kernel steps); loads and stores lift the owning atom's leaf witness along the `∗` spine (`SepLoad*.left`/`.right`, `SepStore*.left`/`.right`) without any AC certificate, while sub-block writes update enclosing regions via `AgreesOutside` frame conditions.
- **Weakest Preconditions (`SepLogic/WP`, `SymBlock`, `SymWP`, `LoopTactics`):** `SepWP` and panic-aware `SepWPp` (`wp_entry` / `wpp_entry`, `sym_block`, `wp_sym_steps`, `wp_steps`, `wp_call` / `wpp_call` / `wpp_call_frozen`, `wp_if`, `wp_loop_measure` / `wp_loop_list` / `wp_nested_loop`, `wp_done`) provide forward symbolic execution that threads a live spatial context `P : SepProp` across basic blocks, loops, and framed subroutine or extern-hook calls without exposing raw memory state or the underlying trace relation in proof goals.
- **Calling Conventions, Control Flow, and Relocatable Code (`Abi/`, `CType/`, `Hoare/`, `ObjectLoad`, `ProgramReflection`):** Compositional `Spec` builders and proof rules for `c_type_spec` (`@[ctype_simp]`), AAPCS64 (`Spec.split`, `Spec.fn*`), and `extern "Rust"` calling conventions (`Spec.rustPair`, `Spec.rustOption64`, `Spec.rustOption8`, `Spec.rustResult64`, `Spec.rustSret`), trace-agnostic `subroutine_ok` introduction/outcome combinators (`subroutine_ok_intro`, `subroutine_ok_outcome_intro`, `subroutine_ok.to_outcome`, `subroutine_ok.mono_outcome`), Floyd-Hoare loop invariants and partial-correctness safety (`safe_until`, `safe_reaches`, `safe_subroutine_ok`, `wp_idx`, `SepWP_idx`), base-address independence of relocatable ELF loading (`Program.ofImage_eq_rebase`), and $O(\log N)$ reflective instruction/symbol lookup (`WordTree`) for compiler-emitted binaries.

## `SepWP` Tactics (`ProofLib/SepLogic/WP.lean` & `Solver.lean`)

The `wp_*` tactic suite is designed to **fix automatically or fail fast** with actionable diagnostics rather than hanging on expensive definitional equality checks or emitting generic `unsolved goals` errors:

1. **Frame Matching & Entailment (`wp_frame_split`, `wp_sep_access`, `sep_entail`, `sep_focus`):**
   - Closes both satisfaction goals (`m ⊨ Q` from `h : m ⊨ P`) and direct heap entailments (`P ⊢ Q`), automatically splitting enclosing `memRegion p n` atoms for sub-cells `[q, q + w)` and coalescing contiguous cells/slices back into `memRegion p n` on demand when direct matching fails.
   - Strips `Expr.mdata` wrappers and normalizes *both* the target (callee precondition / postcondition) and the current spatial context with the `[wp_norm, arm64_norm]` pipeline (unfolding `stackFrame`/`stackFrame16`/`stackFrame32` and substituting local `sf.sp = …` equalities).
   - Folds chained 64-bit literal address offsets (`x - a - b`, `x - a + b`, `(x + a) - b`, `(x + a) + b`, `x + -a`) into canonical `x ± c` form via `[wp_norm]` simprocs (`reduceBV64SubSub`, `reduceBV64SubAdd`) and `foldBV64OffsetTop?` (`reduceBV64AddSub`, `reduceBV64AddAdd`, `bitvec64_add_neg_lit_eq_sub`).
   - Compares spatial atoms strictly at `withReducibleAndInstances` transparency and guards primitive points-to atoms (`↦₈`, `↦₁₆`, `↦₃₂`, `↦₆₄`, `↦₁₂₈`, `↦b`, `↦₆₄*`) against unfolding or matching local free variables (such as typos that become auto-bound implicits).
   - On failure, reports the exact unmatched atom(s) and available spatial candidates (`frame_split: no match for … in precondition; candidates: …`).
   - When the greedy matcher fails, `wp_frame_split` falls back to the backtracking frame solver `sep_frame` (`ProofLib/SepLogic/FrameInfer.lean`), which infers the frame, backtracks over ghost metavariable instantiations, carves/merges `stackAt`/`memRegion` regions, and reports the unmatched goal atom or unprovable value side condition. Use `sep_frame` directly (or `sep_frame_apply SepWP.frame_post_entails h`, `SepWP.frame_auto`, `SepWP.call_subroutine_frame_auto`) to avoid writing `(F := …)`.

2. **Subroutine & Tail Calls (`wp_call`, `wpp_call`, `wpp_call_frozen`, `wp_tailcall`):**
   - Checks up front that the current PC is neither an unresolved `if … then … else …` branch nor already at `target_pc`; `wp_tailcall` steps an unconditional `B target` branch if needed and discharges `subroutine_ok`, `HookOk`, or `HookSat` contracts at `target` using the current link register `x30`.
   - On `SepWPp` goals (or a `SepWPp.of_sepWP` / `SepWPp.of_sepWP_frozen` segment that has stepped to a call site), `wpp_call hcall` (and `wp_call hcall`, which delegates to `wpp_call` automatically) transitions the segment, infers `ret_pc` from `lr` and the spatial frame `F` via `sep_frame`, preserves `img.FrozenLoaded` and `symtab = img.symtab` (`ProofLib/SepLogic/WPFrozen.lean`, `wpp_call_frozen`), and discharges panic obligations (`Spec.noPanic`, `Spec.allowPanic`, `Spec.panicsOr`, `Spec.allowPanicWhen`, or explicit `(on_panic := term)`).
   - Code-derived call cuts (`ProofLib/SepLogic/CodeLookup.lean`, `ProofLib/SepLogic/WP/ControlTactics.lean`): `wp_steps_to_call`, `wp_steps_to_ret`, `wp_steps_to_insn`, `wp_cut_call`, `sepWPp_cut_call`, and `code_call_addr%` / `reloc_call_off%` / `words_ret_off%` step to or cut at call/return sites by symbol name or instruction pattern without hard-coding byte offsets.
   - `[callee_saved_split]` and `split_callee_saved` (`ProofLib.SimpAttrs`, `ProofLib.CoreLemmas`, `ProofLib.SepLogic.WP`) unpack `CalleeSavedPreserved` / `CallingConventionPreserved` into per-register `readReg64`/`readReg32` equalities with `CalleeSavedPreserved.rfl` and `CalleeSavedPreserved.trans`.
   - `sep_eq` (`ProofLib.SepLogic.Solver`) closes `SepProp` equality goals `P = Q` via `sepProp_eq_of_entails` and `sep_entail`.
   - `wp_entry` / `wpp_entry` (`ProofLib/SepLogic/Entry.lean`) and `wp_init` (`wp_start`, `wpp_init`) unfold `@[wp_unfold]` / `declare_rebased_program` and `.rebase` program wrappers automatically at subroutine entry.
   - Discharges callee precondition obligations in three dependency-ordered phases:
     1. Register-passed ghost bindings (`lhs = rhs` where `rhs` contains ghost metavariables).
     2. Spatial framing (`SepFrame` / `m ⊨ …`), instantiating memory-held ghost fields.
     3. Pure side conditions using local hypotheses (`wp_assumption`, `assumption`, `bv_omega`, `omega`, `bv_decide`).
   - Detects underdetermined ghost variables (e.g. a ghost field appearing only inside an inequality like `g.extra.toNat + 46884 < …`) and suggests passing the ghost argument explicitly (`wp_call hcall <ghost_arg>`).
   - Reports call-site setup or precondition failures with the specific failed conjunct and unified ghost bindings rather than a generic `wp_focus_close: unsolved goals`.
   - Contract lookup (`ProofLib/SepLogic/WP/Apply.lean`, `import ProofLib.SepLogic.WP.Apply`): `wp_apply` finds the contract for the current PC among local `subroutine_ok` hypotheses (also `∀`-quantified ones) and `@[wp_spec]` lemmas (indexed by callee address), fills the contract's parameters (address unification, local assumptions, instances, `autoParam` tactics) and calls `wp_call`; `wp_apply?` prints the explicit `wp_call`; `wp_spec_intro` adds registered contracts as hypotheses before entry generalization; `wp_apply (frame := P)` uses a `SepFrameInfer.FrameProc` for the callee precondition.

3. **Single-Instruction Stepping (`wp_step`):**
   - Wraps dispatch alternatives in `tryCatchRuntimeEx` and heartbeat caps so runtime exceptions (`maximum recursion depth`, heartbeat timeouts) in one candidate rule cleanly fall through to the next rule.
   - Inspects effective addresses up front (`preferHi64ForAddr`) on 32-bit loads/stores (`LDR`, `LDUR`, `LDRSW`, `STR`, `STUR`) over `↦₆₄` cells to try the matching high-half (`offset % 8 == 4`) or low-half (`offset % 8 == 0`) rule first.
   - When no step rule applies, prints the instruction mnemonic/operands, the current PC, and all points-to atoms in the spatial context.

4. **Multi-Instruction Stepping (`wp_steps [n]`):**
   - Accepts an optional step bound (e.g. `wp_steps 20`; default `128`).
   - Stops at subroutine call boundaries (`BL`/`BLR`), return/target boundaries (`RET`), and tail-call boundaries (`B` to another function's entry address) with an `info` diagnostic message.
   - At conditional branch (`ite`) PCs, attempts automatic branch resolution from local hypotheses (`simp` / `decide` / `bv_decide`). If the branch condition cannot be determined, stops with `wp_steps: branch condition unresolved at pc …; use wp_if`.

5. **Postcondition Closing (`wp_done`):**
   - Automatically unfolds `CalleeSavedPreserved`, `CallingConventionPreserved`, `StackPreserved`, and `SubroutinePost` in both hypotheses and the goal.
   - Before invoking expensive arithmetic or SAT search, normalizes the LHS and RHS of register and memory postcondition equalities and checks syntactically for concrete value or offset mismatches, failing immediately with an `actual` vs `expected` diff.
   - Scopes internal closers with heartbeat caps and reducible transparency so wrong postconditions fail in seconds.

## Performance Pitfalls and How Normalization Is Ordered

Symbolic execution over 50–100+ instruction blocks builds deep `Arm64.State` update spines and address arithmetic expressions. Three classes of normalization bugs can cause multi-minute kernel or elaborator hangs if reintroduced:

1. **Never use `rfl`-proved `Arm64.State` lemmas in `arm64_norm` / `wp_norm`, or `rfl` on `State` projections:**
   - When `simp` rewrites using a theorem with `SimpTheorem.rfl == true` (or a simproc returning `proof? := none`), it omits the theorem application from the proof term and emits `of_eq_true (eq_self _)`, forcing the kernel to verify `proj(State, i, s0) ≡ proj(State, i, s_N)` by definitional equality.
   - Lean's `is_def_eq_proj` optimistically attempts `is_def_eq(s0, s_k)` *before* reducing the projection, triggering structure eta expansion across every field of `Arm64.State` at every spine node ($O(2^N)$ kernel recursion).
   - **Rules:**
     - Prove every `arm64_norm` / `wp_norm` theorem whose statement mentions `Arm64.State` via `by cases s; rfl` (or `by cases s; constructor <;> exact id` for `Iff`) or existing field lemmas — never `:= rfl` or `:= Iff.rfl`. Enforced in CI by `#arm64_check_no_rfl_state_lemmas` (`ProofLib.VCGen`).
     - Never register a `def` by name in `arm64_norm`, `wp_norm`, or other custom `register_simp_attr` sets when it is meant to rewrite via equation lemmas: in Lean 4, `addDeclToUnfold` places every non-recursive `def` (`hasSmartUnfolding = false`) into `SimpTheorems.toUnfold`, so pre-pass `dsimp` delta-unfolds it (`proof? := none`) into unreduced `match` terms that can hang the kernel's `isDefEq` check. Register equation lemmas (`attribute [arm64_norm] Foo.eq_1 Foo.eq_2`) or explicit `@[simp, arm64_norm] theorem`s instead; enforced in CI by `#assert_simp_set_no_delta_unfold` ([`ProofLib/Testing/SimpSetUnfoldLint.lean`](Testing/SimpSetUnfoldLint.lean)).
     - All `reduceState*` pre-simprocs (`reduceStatePC`, `reduceStateMem`, `reduceStateStatus`, `reduceStatePState`, `reduceStateBrk`, `reduceStateOracle`, `reduceStateOracleIdx`) construct explicit $O(\text{spine})$ `Eq.trans` chains of `State.<field>_*` theorems (`extractState*Proof`).
     - Close field-equality goals like `s0.mem = (s0.setPC _).mem` using `simp only [wp_norm, arm64_norm]` or `proveMemEqExpr?`, never `rfl` or `decide`.

2. **Normalization ordering (`↓` pre-simprocs before post-order literal and algebraic rules):**
   - **Pre-order (`↓`):**
     - `reduceState*` peels `State` projections (`s.pc`, `s.mem`, `s.status`, `s.pstate`, `s.sp`, `s.readReg64`) along the state-update spine before `simp` visits intermediate register values or memory stores.
     - `reduceBitVecAddAssoc` (`↓`) and `reduceBitVecAddSub` (`↓`) fold `(base + c1) + c2` and `(base + c1) - c2` into `base + (c1 ± c2)` when `c1, c2` are ground `BitVec` literals. `evalNatLit?` and `evalBitVecLit?` evaluate arithmetic structurally on literals without calling `whnf` on `Nat` arithmetic terms.
     - `reduceBitVecAddOfNat64` (`↓` and post) replaces the unguarded `bitvec_add_ofNat_add_ofNat_64` rewrite and is guarded by `Lean.Nat.fromExpr?` on *both* `Nat` operands, ensuring `((a + b) % 2^64)` is never constructed on non-numeral `Nat` expressions (which the kernel would otherwise evaluate in unary via `Nat.rec`).
   - **Post-order:**
     - Complete `BitVec.reduce*` and `Nat.reduce*` builtin simprocs plus custom `dsimproc`s (`reduceBitVecTruncate`, `reduceBitVecMsb`, `reduceBitVecSShiftRight'`, `reduceBitVecTwoPow`, `reduceBitVecOfBool`) are registered in both `arm64_norm` and `wp_norm`, ensuring every operator emitted by `Arm64/Trusted/ISA/Eval.lean` (`MOVN`, `MVN`, `ORN`, `BIC`, `EON`, `NEG`, `SXTW`, bitfields, shifts, condition flags) reduces on concrete literals (preventing unreduced ground terms like `~~~0#64` from hanging the kernel).

3. **Reducibility discipline (`arm64_proof_prelude`):**
   - Use `arm64_proof_prelude` at the top of proof files to set `attribute [local irreducible] Arm64.Program.fetch Arm64.Program.externAt?`.
   - **Do not** mark `Program.fnOff`, generated `*Code` constants, `Program.rebase`, or `Program.fnAddr` as `irreducible`: `Program.fnAddr_rebase` and the literal-folding simprocs rely on `fnOff` reducing to a concrete `BitVec 64` numeral.

## Generating Fetch/Decode Lemmas, Literal-Fetch Linting, and Whole-Code Opcode Exclusion

> [!WARNING]
> **Never check in generated fetch/decode text.** Checked-in theorems whose statements spell out literal ISA AST constructors (`Instr.*`, `Reg.*`, `AddrMode.*`, or anonymous `.ctor` syntax) break across every ISA syntax or decoder refactor. Always generate per-offset fetch/decode lemmas at elaboration time with `gen_fetches` / `gen_decodes` (`ProofLib.GenDecodes`), and use `ProofLib.OpcodeExclusion` (`prove_all_instrs`) for whole-binary instruction exclusion invariants.

### 1. Lean-Side Fetch/Decode Generation (`ProofLib.GenDecodes`)

Given a `Program` constant `widgetCode` whose bytes are reflected into a `WordTree` (`widgetCode_tree : WordTree := word_tree_of% widgetCode` and `widgetCode_code_eq : widgetCode.code = widgetCode_tree.toBytes`), generate per-instruction decode and fetch lemmas directly in Lean (`import ProofLib` or `import ProofLib.GenDecodes`):

```lean
import ProofLib

def widgetCode_tree : WordTree := word_tree_of% widgetCode
theorem widgetCode_code_eq : widgetCode.code = widgetCode_tree.toBytes := by rfl_kernel

-- Tree-level decode lemmas only: elaborates `<prefix>_decode_0x<off>` for each offset.
gen_decodes widgetCode_tree widgetOnly [0x0, 0x4, 0x8]

-- Full Program + rebased fetch lemma family up to `textEnd` (`0xc`):
gen_fetches widgetCode widget 0xc [0x0, 0x4, 0x8]
```

For each 4-byte aligned offset `off` in the range list `[a, b → c, raw d, …]` (`a → b` expands all aligned offsets in `[a, b)`, and `raw d` skips instruction operand normalization), `gen_fetches widgetCode widget <textEnd> [...]` elaborates and kernel-checks:

- `<prefix>_decode_0x<off> : widgetCode_tree.fetchDecodeAt off = some <inst>`
- `@[simp, arm64_norm] <prefix>_fetch_0x<off> : widgetCode.fetch 0x<off>#64 = some <inst>`
- `@[simp, arm64_norm] <prefix>_rebase_fetch_0x<off> (b : BitVec 64) (X : String → Option (State → State)) : (widgetCode.rebase b X).fetch (b + 0x<off>#64) = some <inst>`
- `<prefix>_rebase_fetch_base (b : BitVec 64) (X : String → Option (State → State)) : (widgetCode.rebase b X).fetch b = some <inst>` whenever offset `0x0` is included in the range list (discharging `b + 0#64` directly at the function or image base `b`).

Pass an optional identifier `<root>` before `[...]` (`gen_fetches widgetCode widget 0xc root [...]`) to also emit root-namespace `widgetCode_fetch_0x<off>`, `widgetCode_rebase_fetch_0x<off>`, and `widgetCode_rebase_fetch_base` aliases.

### 2. Linting Hand-Written Literal Fetch/Decode Statements (`ProofLib.LiteralFetchLint` & `ci-tools`)

Two complementary checks reject hand-written fetch/decode statements whose **conclusions** mention literal ISA AST constructors while allowing symbolic instruction variables in step lemmas (`∀ inst, prog.fetch pc = some inst → ...`) and automatically exempting `gen_fetches` / `gen_decodes` output:

1. **Lean linter & audit commands (`ProofLib.LiteralFetchLint`, included in `import ProofLib`):**
   - `linter.literalFetch` (`Bool`, default `true`): runs automatically on every declaration in any module that imports `ProofLib` (including downstream repositories with `-DwarningAsError=true` or `--wfail`).
   - `#lint_literal_fetches [Mod.Prefix]` / `#lint_literal_fetches! [Mod.Prefix]`: audit all non-generated declarations in the current module or imported modules matching `Mod.Prefix` (`!` fails elaboration on any violation).
   - Intentional relocation or unit-test fixtures can opt out with `@[nolint_literal_fetch]` (suppresses both `literalFetchLinter` and `#lint_literal_fetches!`) or `set_option linter.literalFetch false in ...`.
2. **Fast source scanner (`ci-tools lint-literal-fetches`):**
   - Run `cargo run --locked --manifest-path tools/Cargo.toml -p ci-tools -- --root <downstream-repo> lint-literal-fetches` in CI to scan an entire downstream repository in milliseconds before compilation.

### 3. Refactor-Stable Whole-Code Opcode Exclusion (`ProofLib.OpcodeExclusion`)

To prove whole-binary security invariants such as "the binary never executes `SVC`" or "the binary never writes `TPIDR_EL0` via `MSR`" without case-splitting on internal branches of `Arm64.decode`, import `ProofLib` (or `ProofLib.OpcodeExclusion`):

- **Instruction & bitmask predicates:** `Instr.isSvc`, `Instr.isSvc0`, `Instr.isBrk`, `Instr.isMsr`, `Instr.isMsrSysreg`, `Instr.isMsrTpidrEl0` (`sysregTpidrEl0`), and 32-bit word counterparts `isSvcWord`, `isSvc0Word`, `isBrkWord`, `isMsrWord`, `isMsrSysregWord`, `isMsrTpidrEl0Word`.
- **Exact decoder characterisations (`↔` and negative forms):** `decode_isSvc_iff`, `decode_not_isSvc`, `decode_isSvc0_iff`, `decode_not_isSvc0`, `decode_isBrk_iff`, `decode_not_isBrk`, `decode_isMsr_iff`, `decode_not_isMsr`, `decode_isMsrSysreg_iff`, `decode_not_isMsrSysreg`, `decode_isMsrTpidrEl0_iff`, `decode_not_isMsrTpidrEl0`.
- **Architectural preservation theorems:** `execInst_perm_of_not_isSvc0`, `execInst_trace_of_not_isSvc0`, `execInst_tpidrEl0_of_not_isMsrTpidrEl0`, plus small-step bridges `Step.holdsBytes_rx`, `Steps.holdsBytes_rx`, `Step.perm_and_trace_of_noHook`, and `Step.tpidrEl0_of_noMsrTpidrEl0`.
- **Reflective whole-code checker (`prove_all_instrs`, zero `native_decide`):** reduces `Program.allInstrs` / `Code.allInstrs` over `<prog>_code_eq : <prog>.code = <tree>.toBytes` to a linear bitmask pass over `WordTree` leaves checked directly in the Lean kernel:

```lean
import ProofLib

theorem widget_allInstrs_no_svc : widgetCode.allInstrs (!·.isSvc) = true := by
  prove_all_instrs

theorem widget_rebase_fetch_no_svc (b : BitVec 64) (X : String → Option (State → State))
    (addr : BitVec 64) (i : Instr) :
    (widgetCode.rebase b X).fetch addr = some i → ¬ i.isSvc := by
  prove_all_instrs

theorem widget_fetchMem_no_svc {m : Memory}
    (hbase : widgetCode.base.toNat % 4 = 0)
    (hlen : widgetCode.base.toNat + widgetCode.code.length ≤ 2 ^ 64)
    (hH : Obj.HoldsBytes m widgetCode.base widgetCode.code (fun _ => Perm.rx))
    (hexec : widgetCode.ExecOnlyIn m)
    (addr : BitVec 64) (i : Instr)
    (hf : widgetCode.fetchMem m addr = some i) : (!i.isSvc) = true :=
  Program.fetchMem_of_allInstrs_holdsBytes widget_allInstrs_no_svc hbase hlen hH hexec addr i hf
```
